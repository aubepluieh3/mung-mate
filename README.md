# mung-mate (멍메이트) — 동네 강아지 산책 친구 매칭 (협업 버전)

우리 동네에서 **성향이 맞는 강아지 친구를 찾아 같이 산책**하는 앱.

> 이 프로젝트는 **사용자와 함께 단계적으로** 만든다. 작업 방식은 `CLAUDE.md` 참고.

> ## ⛔ `claude-lab/solo/` 는 절대 열어보지 말 것
>
> 같은 기획서로 클로드가 **혼자** 만든 버전이 `claude-lab/solo/mung-mate` 에 있다.
> 팀장이 나중에 **두 결과물을 비교**할 것이다. 한 번이라도 들여다보면 비교가 무의미해진다.
>
> 참고도 안 된다. 막혀도 보지 말고 팀장에게 물어볼 것.
> 이 프로젝트의 설계는 처음부터 팀장과 같이 정한다.

## 왜 만드는가

강아지 산책은 매일 해야 하는데 늘 혼자다. 그런데 견주들은 이런 걸 원한다.

- 우리 개가 다른 개랑 어울릴 기회를 주고 싶다
- 근데 아무 개나 만나면 안 된다 — 덩치, 성격, 중성화 여부가 안 맞으면 사고 난다
- 밤 산책은 혼자 다니기 무섭다
- 어느 길이 산책하기 좋은지 모른다

즉 문제는 "친구 찾기"가 아니라 **"안 맞는 조합을 걸러내는 것"** 이다. 매칭 로직이 이 앱의 핵심.

## 핵심 기능

### 1. 강아지 프로필
- 이름, 견종, 나이, 몸무게, 성별, 중성화 여부
- 성향 태그: `활발함` `겁많음` `사람좋아` `개무서워함` `짖음많음` `입질주의`
- 사진
- 한 계정에 여러 마리 등록 가능

### 2. 매칭
- 위치 기반으로 주변 강아지 탐색 (반경 조절)
- **궁합 점수** — 체급 차이, 성향 태그 충돌, 나이대를 계산해서 점수화
  - 예: `입질주의` × `겁많음` → 낮은 점수 + 경고 표시
  - 예: 3kg 소형견 × 40kg 대형견 → 체급 경고
- 서로 좋아요를 누르면 채팅방 개설

### 3. 산책 약속
- 시간 / 장소 / 예상 소요시간 정해서 약속 생성
- 참여 인원 제한 (1:1 또는 소그룹)
- 노쇼 방지를 위한 간단한 매너 평가

### 4. 산책로
- 사용자가 산책로 등록 (경로, 사진, 한줄평)
- 태그: `배변봉투함있음` `물있음` `그늘많음` `차없음` `목줄풀어도됨`
- 근처 산책로 지도에서 보기

### 5. 산책 기록
- 산책 시작/종료 → 거리, 시간, 경로 자동 기록
- 이번 주 산책 횟수와 거리
- 함께 산책한 친구 목록

## 만들 때 주의할 것

- **안전이 최우선** — 입질/공격성 정보는 숨기지 말고 눈에 띄게 표시할 것
- 정확한 집 주소는 절대 노출하지 말 것 (동 단위까지만)
- 첫 만남 장소는 공개된 장소를 권장하는 안내 넣기

## 같이 이야기하며 정할 것

코드보다 먼저 이야기가 필요한 지점들. 선택지만 늘어놓지 말고,
**내 생각을 먼저 말하고 걸리는 부분을 드러내면서** 같이 결론을 찾는다.

1. 기술 스택 — 서버를 둘 것인가, 로컬 저장으로 갈 것인가
2. 지도 — 실제 지도 API(카카오/네이버/구글)를 붙일 것인가, 직접 그릴 것인가
3. 어디까지 만들 것인가 — 궁합 엔진만 먼저 제대로 만들지, 화면까지 갈지
4. **궁합 점수 계산 규칙** — 이 앱의 핵심이고, 정답이 없는 부분이다.
   어떤 조합을 위험으로 볼지, 감점을 얼마나 줄지, 점수가 높아도 막아야 하는
   조합이 있는지. 여기는 시간을 들여서 같이 설계할 값어치가 있다
5. 배포 형태 (웹 / 모바일)

## 시작하기

```bash
npm install
npm run server     # API + DB (5181). 먼저 띄운다
npm run dev        # 화면 (5180) → http://localhost:5180
npm test           # 판정 룰 테스트
npm run typecheck
node --experimental-strip-types scripts/demo.ts [강아지이름]   # 다른 견주 시점으로 목록 확인(샘플 기준)
```

의존성은 화면(Vite·React)에만 있다. 서버는 Node 내장 `node:http` + `node:sqlite`,
판정 엔진은 `node:test` 로만 검증한다. DB 는 `data/mung-mate.db` 에 생기고 비어 있으면 샘플로 채워진다.

# 1차 개발 결과

## 정한 것

- **기술 스택** — 판정 엔진은 의존성 0(TypeScript + `node:test`), 화면은 Vite + React,
  서버는 Node 내장 `node:http` + `node:sqlite`
- **판정은 서버에서만 돈다** — 처음엔 `localStorage` 로 만들었는데, 그러면 궁합 매트릭스가
  브라우저 번들에 그대로 들어간다. "산식이 노출되면 유리한 태그만 골라 적는다"고 정해놓고
  배포 형태 때문에 원칙이 깨져 있었다. 지금은 화면이 완성된 결과만 받고,
  남의 개 프로필도 클라이언트로 내려가지 않는다
- **지도** — 붙이지 않았다. 정확한 위치 대신 **동 이름과 산책 시간대**로 만날 수 있는지 판단한다
- **궁합 규칙** — 아래 두 단계로 나눴다. 이게 이 프로젝트의 핵심 결정이다

## 궁합 판정은 2단계다

점수 하나로 뭉개면 안전 기능이 무력화된다. `입질주의` × `겁많음` 조합이 다른 조건이 좋아서
70점이 나오면 견주는 "70점이면 괜찮은가" 하고 만난다.

```
1단계  게이트 — 만나면 안 되는 조합을 차단/경고한다 (안전 판정)
2단계  점수  — 게이트를 통과한 상대들의 순위를 매긴다 (순서 결정)
```

**게이트는 견주 진술을 쓰지 않는다.** 체급·나이·성별·중성화 여부처럼 거짓으로 적을 이유가
없는 사실만 본다. 성향 태그는 자기신고라 회피가 쉽고, 안전 판정을 진술에 걸어두면
**룰을 세게 걸수록 데이터가 오염된다.**

| 게이트 룰 | 판정 |
|---|---|
| 4개월 미만 (접종 미완료) | 차단 |
| 체급 3배 이상 차이 | 차단 |
| 발정 중 암컷 × 미중성화 수컷 | 차단 |
| 체급 2배 이상 차이 | 경고 |
| 발정 중 (그 외 상대) | 경고 |
| 미중성화 성견 수컷끼리 | 경고 |
| 노견 × 퍼피 | 경고 |

**점수는 `태그 궁합 × 물리 조건 계수`다.** 만점에서 깎는 방식은 태그를 벌점표로 만들고
가점이 상한에 먹힌다. 태그 쌍의 평균을 쓰므로 태그를 많이 붙여도 유리해지지 않고,
태그가 없으면 점수를 매기지 않아 빈 프로필이 상위권에 오지 못한다.

## 낙인을 만들지 않으려고 한 것

`입질주의` 를 체크할 견주는 없다. 체크하면 매칭이 줄고 낙인만 붙는다. 그래서 뒤집었다.

- **정직에 보상을 준다** — `낯선 개에게 예민해요` 를 체크하면 같은 사정인 견주와 우선 매칭된다
- **`겁많음` 끼리는 가점** — 감점만 주면 정직하게 적은 견주가 매칭을 가장 적게 받고 떠난다
- **점수와 산식을 화면에 노출하지 않는다** — 자기 개가 몇 점인지 알면 기분이 상하고,
  산식이 보이면 유리한 태그만 골라 적는다. 등급 문장만 내보낸다
- **성향 태그는 3개까지만** — 전부 고를 수 있게 두면 다들 전부 골라서 판별력이 0이 된다

## 룰보다 절차를 믿는다

진술 기반 판정은 완벽해질 수 없다. 그래서 **첫 만남 안내는 궁합이 좋아도 똑같이 붙인다.**
점수가 높을 때 안내를 완화하면 그 방심이 사고를 만든다. 실제 사고에서 가장 흔한 대사가
"우리 개는 개 좋아해요"다 — 그래서 `개좋아함` × `겁많음` 은 가점이 아니라 감점이다.

## 만든 것 / 안 만든 것

| 기능 | 상태 |
|---|---|
| 궁합 판정 (게이트 + 점수) | ✅ |
| 만날 수 있는지 (동 + 시간대) | ✅ 반경 조절은 없음 |
| 매칭 목록 화면 | ✅ |
| 내 강아지 프로필 등록 + 로컬 저장 | ✅ 사진·여러 마리 없음 |
| 산책 요청 보내기 | ✅ 받는 쪽 흐름 없음 |
| 서로 좋아요 → 채팅 | ❌ |
| 산책 약속 (시간/장소/인원/매너평가) | ❌ |
| 산책로 (등록/태그/지도) | ❌ |
| 산책 기록 (거리/시간/주간 통계) | ❌ |

# 2차 개발 과제

## 높음

1. **`tagTrust`(프로필 노후화) 정리** — 6개월 지난 프로필은 태그 궁합을 중립으로 당긴다.
   개념은 맞지만 **화면에서 설명되지 않는 등급 차이**를 만든다. 같은 `겁많음` 끼리인데
   등급이 다른 이유를 견주가 알 수 없다. 빼거나, 카드에 "프로필이 오래됐어요"를 표시할 것
2. **요청을 받는 쪽 흐름** — 지금은 보내기만 된다. 수락/거절이 없다
3. **만날 상대가 부족하다 — 안전이 아니라 공급이 병목이다**

   13명 전원 시점으로 측정한 결과다.

   | 견주 | 체급 | 만날 수 있음 | 못 만남 | 차단 | 가능률 |
   |---|---|---|---|---|---|
   | 토리 | 8kg | 8 | 1 | 3 | 67% |
   | 두부 | 12kg | 6 | 5 | 1 | 50% |
   | 까미 | 6kg | 3 | 5 | 4 | 25% |
   | 초코 | 30kg | 2 | 2 | 8 | 17% |
   | 할부지 | 11kg | 0 | 11 | 1 | 0% |
   | 흰둥 | 25kg | 0 | 6 | 6 | 0% |
   | 새싹 | 4kg | 0 | 0 | 12 | 0% |

   **평균 3.4명 / 12명(28%). 13명 중 3명은 한 명도 만날 수 없다.**
   원인을 나누면 **차단(안전) 52건 vs 동네·시간대 불일치 60건** — 만남을 막는 주범이 안전이 아니다.

   할부지가 증거다. **차단은 1명뿐인데 만날 사람이 0명**이다. 합정동에서 아침에만 걷기 때문이다.
   궁합 엔진을 더 정교하게 만들어도 이 견주는 앱을 지운다.

   기획서는 "문제는 안 맞는 조합을 걸러내는 것"이라고 했지만, 걸러내기는 이미 된다.
   **2차에서는 궁합 룰을 다듬는 것보다 공급을 늘리는 쪽이 우선이다.**

   - 초코(30kg)는 8명이 차단된다. 소형견이 많은 동네에서 대형견은 구조적으로 고립된다.
     **체급별로 기본 반경을 다르게** 두는 게 맞다 — 큰 개는 원래 멀리 걷는다
   - 동네·시간대를 안 적으면 매칭이 아예 안 되는데 지금은 선택 항목이다. 필수로 받아야 한다

## 중간

4. **견주(계정) 개념** — 지금은 개↔개 매칭인데 실제로 약속을 잡는 건 견주↔견주다.
   한 계정에 여러 마리도 여기 딸려온다
5. **그룹 산책의 발정 문제** — 발정 암컷이 근처에 있으면 **수컷끼리 싸움이 난다.**
   지금은 1:1 판정만 하므로 그룹 산책을 붙일 때 반드시 다시 봐야 한다
6. **나이를 생년월로 받기** — 지금은 저장 시점 나이가 고정된다
7. **태그 평균 방식의 부작용** — 태그를 정확하게 여러 개 적은 사람이 손해를 본다.
   `겁많음`+`예민해요` 둘 다인 개끼리는 78점인데 `예민해요` 만인 개끼리는 100점이다.
   평균 대신 최악 쌍에 가중치를 주는 방식을 검토할 것

## 낮음

8. 산책 약속, 산책로, 산책 기록, 채팅, 사진, 여러 마리, 지도, 매너 평가
9. 상충 태그 동시 선택 차단 (`활발함` ↔ `차분함`)
10. 반경 조절 (좌표 기반 거리 계산)
