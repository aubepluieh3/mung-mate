# mung-mate (멍메이트) — 동네 강아지 산책 친구 매칭 (협업 버전)

우리 동네에서 **성향이 맞는 강아지 친구를 찾아 같이 산책**하는 앱.

> 이 프로젝트는 **사용자와 함께 단계적으로** 만든다. 작업 방식은 `CLAUDE.md` 참고.

> ## ⛔ `claude-lab/solo/` 는 절대 열어보지 말 것
>
> 같은 기획서로 클로드가 **혼자** 만든 버전이 `claude-lab/solo/mung-mate` 에 있다.
> 팀장이 나중에 **두 결과물을 비교**할 것이다. 한 번이라도 들여다보면 비교가 무의미해진다.
>
> 참고도 안 된다. 막혀도 보지 말고 팀장에게 물어볼 것.
> 이 프로젝트의 설계는 처음부터 팀장과 같이 정한다.

## 왜 만드는가

강아지 산책은 매일 해야 하는데 늘 혼자다. 그런데 견주들은 이런 걸 원한다.

- 우리 개가 다른 개랑 어울릴 기회를 주고 싶다
- 근데 아무 개나 만나면 안 된다 — 덩치, 성격, 중성화 여부가 안 맞으면 사고 난다
- 밤 산책은 혼자 다니기 무섭다
- 어느 길이 산책하기 좋은지 모른다

즉 문제는 "친구 찾기"가 아니라 **"안 맞는 조합을 걸러내는 것"** 이다. 매칭 로직이 이 앱의 핵심.

## 핵심 기능

### 1. 강아지 프로필
- 이름, 견종, 나이, 몸무게, 성별, 중성화 여부
- 성향 태그: `활발함` `겁많음` `사람좋아` `개무서워함` `짖음많음` `입질주의`
- 사진
- 한 계정에 여러 마리 등록 가능

### 2. 매칭
- 위치 기반으로 주변 강아지 탐색 (반경 조절)
- **궁합 점수** — 체급 차이, 성향 태그 충돌, 나이대를 계산해서 점수화
  - 예: `입질주의` × `겁많음` → 낮은 점수 + 경고 표시
  - 예: 3kg 소형견 × 40kg 대형견 → 체급 경고
- 서로 좋아요를 누르면 채팅방 개설

### 3. 산책 약속
- 시간 / 장소 / 예상 소요시간 정해서 약속 생성
- 참여 인원 제한 (1:1 또는 소그룹)
- 노쇼 방지를 위한 간단한 매너 평가

### 4. 산책로
- 사용자가 산책로 등록 (경로, 사진, 한줄평)
- 태그: `배변봉투함있음` `물있음` `그늘많음` `차없음` `목줄풀어도됨`
- 근처 산책로 지도에서 보기

### 5. 산책 기록
- 산책 시작/종료 → 거리, 시간, 경로 자동 기록
- 이번 주 산책 횟수와 거리
- 함께 산책한 친구 목록

## 만들 때 주의할 것

- **안전이 최우선** — 입질/공격성 정보는 숨기지 말고 눈에 띄게 표시할 것
- 정확한 집 주소는 절대 노출하지 말 것 (동 단위까지만)
- 첫 만남 장소는 공개된 장소를 권장하는 안내 넣기

# 만든 것 — 최소 버전

**이 앱은 질문 하나에만 답한다. "이 개랑 우리 개가 만나도 되나?"**

```bash
npm install
npm run dev        # http://localhost:5180
npm test
npm run typecheck
```

서버는 없다. 프로필은 브라우저에, 이웃은 `sample/neighborhood.ts` 에 있다.

## 판정 규칙

| 규칙 | 판정 |
|---|---|
| 4개월 미만 (접종 전) | 차단 |
| 체급 3배 이상 차이 | 차단 |
| 중성화하지 않은 암수 | 차단 |
| 체급 2배 이상 차이 | 경고 |
| 미중성화 성견 수컷끼리 | 경고 |
| 노견 × 퍼피 | 경고 |

**바꾸기 어려운 사실만 본다** — 체급·나이·성별·중성화 여부. 견주 진술(성향, 발정 여부)은
쓰지 않는다. 회피가 쉬워서 룰을 세게 걸수록 데이터가 오염된다. 정직하게 적은 소수만
손해를 보고 위험한 케이스는 그대로 통과한다.

**차단이든 경고든 이유를 반드시 보여준다.** 이유를 모르면 견주는 앱의 판단을 신뢰하지 않고,
무엇이 위험한지 배우지도 못한다.

**첫 만남 안내는 판정 결과와 무관하게 항상 붙인다.** "만나도 좋아요"일 때 안내를 완화하면
그 방심이 사고를 만든다. 룰이 놓친 건 절차가 잡는다.

## 왜 이렇게 줄였나

`v1-full` 태그에 전체 버전이 있다. 궁합 점수, 산책 약속, 산책로, API 서버까지
**3681줄 / 테스트 99개**였다. 지금은 **827줄 / 테스트 18개** — 4.5배 작다.

무엇을 버렸고 왜 버렸는지가 이 프로젝트에서 배운 것이다.

- **궁합 점수 (189줄 + 테스트 16개)** — 태그 매트릭스, 물리 계수, 신뢰 가중치, 등급 6단계,
  원인 판별을 다 만들었는데 실제로 하는 일은 **평균 3.4명의 순위를 매기는 것**이었다.
  가장 오래 붙잡고 튜닝한 부분이 효용은 가장 낮았다
- **API 서버 (432줄)** — 서버로 옮긴 큰 이유가 "궁합 산식을 브라우저에서 숨긴다"였다.
  점수를 버리니 숨길 산식이 없다. 판정 규칙은 오히려 **공개해야 하는 정보**다
- **성향 태그** — 점수에만 쓰였다. 판정에 안 쓰는 정보를 물어보면 견주는 "이걸 왜 적나" 싶다
- **산책 약속 · 산책로** — 각각 근거가 있어서 넣었지만(공급 문제 해결 / 콜드스타트 대비),
  핵심 질문에 답하는 데는 필요하지 않다

## 남은 문제

측정한 결과 **만남을 막는 주범은 안전이 아니라 공급**이다. 전체 버전에서 13명 전원 시점으로
재보니 평균 가능률 28%, 3명은 한 명도 만날 수 없었다. 그중 한 명은 **차단이 1명뿐인데
만날 사람이 0명**이었다 — 동네와 시간대가 안 맞아서다.

- **동네 인접 관계를 손으로 적어야 해서 마포구 4개 동뿐이다.** 좌표로 거리를 계산하면
  인접 데이터 없이 지역이 넓어지고, 반경 조절과 체급별 반경(대형견은 원래 멀리 걷는다)이
  같이 딸려온다
- 대형견은 소형견이 많은 동네에서 구조적으로 고립된다 (12마리 중 8마리 차단)
- 사진, 여러 마리 등록, 채팅, 산책 기록은 손대지 않았다
